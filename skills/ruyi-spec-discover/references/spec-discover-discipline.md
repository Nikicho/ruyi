# Spec Discover Discipline

## 1. 反推边界

代码反推 spec 只能发现“可能的规范”，不能直接证明团队已经接受该规范。

因此反推结果默认是 `spec-candidate`，不是正式 spec。

## 2. 优先提炼对象

- 多处重复出现的组件用法。
- 公共组件的稳定 props、事件、插槽、状态约定。
- 模块目录、service、store、route 的组织方式。
- API response、错误处理、鉴权、权限、分页、排序等稳定对接模式。
- 测试文件中反复出现的验收和 mock 约定。

## 3. 不应提炼对象

- 单个页面的临时文案。
- 一次性业务特例。
- 未验证的猜测。
- 过时、孤立或明显废弃的代码。
- 只因为代码存在就推断出的业务规则。

## 4. 证据要求

每条候选规则至少应有一个代码证据路径。

如果只有一个证据路径，必须把适用范围写窄，并在待确认问题中标明“是否可提升为通用规则”。

## 5. 目标路径

- 跨模块共享规则：`references/shared/<domain>/<topic>.md`
- 具体模块规则：`references/modules/<module>/<topic>.md`
- 顶层核心规则：只在确实属于项目级基线时使用，例如 `coding-baseline.md`。

同一功能或公共组件必须持续指向同一个目标目录。
